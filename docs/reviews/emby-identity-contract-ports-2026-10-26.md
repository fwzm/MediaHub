# Emby 协议与恢复身份契约移植

本批基于b094c25dc160ba2e233c712fcfe5736a3911a2f7，沿用既有feature分支与Draft72。
对照旧47eca350架构分支，将有用行为接入当前生产接口，保留现有ServerType、凭据存储、世代保护和已实现能力。

## 改动及行为

| 触发条件 | 修复前 | 修复后 |
|---|---|---|
| Emby根地址带外部空白、endpoint无或有多个前导斜线 | 可能拼出错误路径 | 清除根地址外部空白，保留反代路径与单个emby前缀，endpoint保持一个分隔符；空根地址拒绝 |
| 客户端身份字段含引号/反斜线，或UserId为空 | 直接插值、空UserId仍生成字段 | 五个身份字段转义；空白UserId不生成可选字段 |
| 恢复响应用户Id缺失、为空、空白或与已存用户不一致 | 世代校验后直接发布Authenticated | 返回INVALID_RESPONSE，不进入已登录；保留会话及令牌 |
| Emby探测明确返回Jellyfin产品 | Id/Version有效即接受 | 拒绝，返回PARSE与固定的选择Jellyfin提示 |
| Jellyfin探测明确返回其他产品 | Id/Version有效即接受 | 拒绝，返回PARSE，不回显任意产品名 |
| ProductName缺失、null或空白 | 现有兼容夹具接受 | 保持兼容；Id/Version仍须有效 |

身份头仍为X-Emby-Authorization，令牌仍独立使用X-Emby-Token，未采用旧分支的Authorization改名。
恢复仍先匿名核对远端服务器身份，再执行当前认证尝试的世代检查；仅真实401沿用过期清理路径。
当前取消、lease/epoch、403/网络/协议异常保留凭据的约束继续保留。
旧中央协调器把用户不一致视为Invalidated并清除会话，本批采用当前INVALID_RESPONSE保留策略，不声称逐项完全相同。

ProductName兼容决策依据是已有缺失字段测试，以及[Jellyfin官方生成SDK的PublicSystemInfo](https://typescript-sdk.jellyfin.org/interfaces/generated-client.PublicSystemInfo.html)：字段可选且可为空。
由此保留已有缺失字段行为，只增加明确错误产品的识别；不采用旧分支的强制存在条件。
产品声明仍是协议嗅探信息，不能作为服务器真实性或账号权限证明。
