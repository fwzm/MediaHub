# 自签证书 HTTPS 端到端复验计划

## Context

上一轮修复了 `PlaybackCoordinator.ResolveAsync` 的证书策略缺陷（先前硬编码 `NetworkPolicy.FollowSystem`，导致已确认指纹的自签服务器能浏览但不能播放），并已通过构建与单测。但"真实自签服务器上的播放"在 TASKS.md 与 ADR-W007 中仍是 `NOT_RUN`。

本轮目标：在本机真实网络栈上复验修复，并把结果如实登记：

1. 指纹信任路径：添加自签 HTTPS 服务器 → 出现指纹确认弹窗 → 确认后添加成功 → 起播且实际出画面。
2. "该台不校验"路径：同样能连、能播。
3. 取消路径：不添加服务器、不落指纹、不写凭据。

约束：不把账号密码写进仓库；未验到的不得标通过；如本地无法复刻，直接说明卡点。工作区为不可信目录，因此验证工装一律放在仓库外 `D:\mh-verify`，仓库内只更新验证状态文档。

## 方案

### 1. 仓库外 HTTPS 自签工装

新建 `D:\mh-verify\TlsProxy\`（.NET 10 Kestrel 控制台）：

- 进程内生成自签证书（CN=MediaHub Self-Signed Verify，SAN=localhost + 127.0.0.1，服务器认证 EKU），启动时打印 `SHA-256` 大写指纹。
- 监听 `https://127.0.0.1:<port>`，其余请求反向代理到现有 HTTP `MockServerHost`（复用既有 Emby mock 的 API 语义）。
- 媒体路由 `/emby/Videos/*/stream*` 在 TLS 边缘本地提供 `D:\mh-media\queue-a.mp4`（30s、640×360、约 4 MB），实现 RFC 7233 Range/206；既有夹具 `sample-av.mp4` 仅 4s，不足以稳定截图。
- 每个请求记录：方法、路径、`X-Emby-Token` 是否携带、Range、响应状态。这同时是"媒体流确实经应用 HTTP 栈、带会话、走 TLS"的证据。

### 2. 启动现有 mock 与客户端

- `windows\tools\MockServerHost\bin\x64\Debug\net10.0-windows\win-x64\MockServerHost.exe --items 6`（HTTP 回环端口，登录账号为 mock 内置 `tester/secret`，仅用于本次运行，不写入仓库）。
- 客户端直接用已构建产物 `D:\mh-out\x64\Debug\net10.0-windows10.0.19041.0\win-x64\MediaHub.exe`。
- 运行前备份 `%LOCALAPPDATA%\MediaHub\settings.json` 与 `credentials\`，结束后还原，避免把 mock 凭据留在本机。

### 3. 驱动脚本（仓库外）

`D:\mh-verify\run-selfsigned-verify.ps1`，复用仓库既有 UIA 模块 `windows\tools\acceptance\lib\MhUia.psm1`（`Find-MhAppElement`、`Set-MhValue`、`Invoke-MhElement`、`Get-MhPlayerState`、`Get-MhVideoRect`、`Save-MhScreenshot`、`Add-MhCheck/Save-MhRun`）。若模块因不可信目录无法导入，则退回脚本内置的最小 UIA 实现。

证据输出到 `D:\mh-verify\evidence\`（截图、代理日志、mock 日志、UI dump、results.json/md）。

### 4. 验证项

- **A 指纹信任**：媒体源 → 添加媒体源（类型默认 Emby）→ 填 `https://127.0.0.1:<port>/emby`、账号密码 → 登录并添加 → 断言弹窗标题"信任该服务器的证书？"且弹窗内 SHA-256 与代理打印一致 → 点"信任该指纹（推荐）" → 断言"已添加媒体源"、"已连接"；读 `settings.json` 断言 `TrustedCertificateSha256` 等于该指纹、`AllowUntrustedCertificate=false`；断言 vault 有对应条目。
- **B 指纹路径播放**：媒体库 → Movies → 首个条目 → 详情 → 播放；断言 `hwdec=` 与 `分辨率 640 × 360` 出现、位置在推进；截取窗口并检查 mpv 子窗口矩形内像素非全黑/颜色数足够，作为"实际出画面"证据；代理日志断言 `/Videos/.../stream` 请求带 token 且收到 Range、返回 200/206。
- **C 该台不校验**：删除该源 → 同参数重加 → 弹窗选"该台不校验" → 断言"已添加媒体源（该服务器不校验证书）"、"已连接"、`AllowUntrustedCertificate=true` 且无指纹 → 再次起播并做同样的画面断言。
- **D 取消不留痕**：删除该源 → 记录 settings 与 vault 字节哈希 → 重加 → 弹窗点"取消" → 断言"未添加媒体源"/"已取消"、列表无该源、`settings.json` 中 Servers 未新增、vault 文件哈希不变。

### 5. 状态登记

仅对实际通过的项目修改：

- `TASKS.md` 顶部"2026-11-12 Windows 客户端代码审查与缺陷修复"条目中真实自签服务器播放的 `NOT_RUN` 行。
- `windows/docs/adr/ADR-W007` §5 对应状态。
- 记录日期、自签证书指纹、验证方式与证据位置；失败的项保留 `NOT_RUN` 并写明失败现象或环境卡点。

### 6. 清理

停止客户端、mock、代理进程；还原 `%LOCALAPPDATA%\MediaHub` 备份；不修改仓库内任何测试夹具或凭据文件。

## Verification

以脚本自身 `results.json` 的 pass/fail 为准；同时人工核对：弹窗指纹与代理指纹逐字符一致、截图内视频区域确有画面、代理日志中媒体请求携带会话头。若任一环节无法复刻（如证书/客户端校验不配合），停止并如实报告卡点，不伪造通过。
