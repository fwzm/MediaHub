## A1 · Seek —— EXECUTED_PASS

用 `RangeValuePattern` 驱动**真实的 SeekSlider**（`player.seekslider`），不是合成点击。

| 步骤 | Slider 设定 | 引擎读数 |
| --- | --- | --- |
| 播放中基线 | `RANGE 0.2324` | `0:20 / 1:30` |
| 前跳 | `0.60` → 实际 `0.60000` | **`0:59`**，+6 秒后 `1:07` |
| 后跳 | `0.15` → 实际 `0.15000` | **`0:18`** |

0.60 × 90 s = 54 s，读数 0:59（含 4 秒等待期间的自然推进）；0.15 × 90 s = 13.5 s，读数 0:18（同）。
**两个方向都验证了目标位置，没有使用「after > before」这个在后跳时天然错误的判据。**
前跳后继续采样到 1:07，说明跳转后播放仍在推进、未卡死。

## A2 · 正常退出与连接释放 —— EXECUTED_PASS

**关键方法修正**：`HttpListener` 由 **http.sys 内核驱动**承载，回环转发层的端口**不会**出现在所属进程的
TCP 监听表中。上一轮用 `Get-NetTCPConnection -OwningProcess` 过滤恒为空，**无法区分「已释放」与「从未建立」**。
改用 `netsh http show servicestate` 读取驱动实际持有的注册。

| 时点 | http.sys 注册 |
| --- | --- |
| WebDAV 播放中 | **`38101`** ← 回环转发层确实已建立 |
| 退出播放页后 | **空** ← 监听器已释放 |

这满足了「**未成功创建转发层不计为已释放**」的要求：本轮先证明它存在（38101），再证明它消失。

## 本轮修掉的一个可寻址性缺陷

`SeekSlider` 此前**没有 AutomationId**。第一次跑 Seek 时得到 `NOT_FOUND player.seekslider`，
而时间轴仍在 `0:20 → 0:28 → 0:36 → 0:43` 变化 —— **那是自然播放推进，不是 Seek**。
若当时只用「时间在变」作为判据，就会把一次完全没执行的 Seek 报成通过。
控件补上 id 后，Seek 才真正被执行并读出目标位置。
